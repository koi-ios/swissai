# vLLM v0.32.0: how every on-disk cache is wired (`vllm_0320`)

Source: `vendor/vllm-v0.32.0`, git tag `v0.32.0`, commit `5df63a7` (committed 2026-10-17). That the platform's
`vllm_base` image ships exactly this release is **UNVERIFIED**: there is no image manifest under `vendor/`.
Everything below comes from source; nothing was run. Paths are relative to `$OPP`. A few lines of PyTorch 2.13,
DeepJIT, FlashInfer 0.7.0.post1, TileLang 0.1.12 and vLLM's vendored FA4 are cited where vLLM's behaviour depends on
them. Those libraries are covered in depth by other topics.

**Default code path.** vLLM 0.32.0 builds against torch 2.13.0 `vendor/vllm-v0.32.0/pyproject.toml:10` and runs at `-O2` by
default `vendor/vllm-v0.32.0/vllm/config/vllm.py:427`. With those defaults, torch.compile uses AOT plus the "mega" artifact (§2–3),
Inductor runs through the standalone adaptor (§5), FlashInfer autotune is on (§9), DeepGEMM warmup is `relax` (§7) and
JIT warmup is on (§13).

## 1. Cache root, import-time env changes, and the env part of every compile hash (`vllm_root`)

- **Variable and default.** `VLLM_CACHE_ROOT` `vendor/vllm-v0.32.0/vllm/envs.py:712`. Its default is `<cache root>/vllm`
  `vendor/vllm-v0.32.0/vllm/envs.py:715`, where `<cache root>` is `$XDG_CACHE_HOME` `vendor/vllm-v0.32.0/vllm/envs.py:340` or else
  `~/.cache` `vendor/vllm-v0.32.0/vllm/envs.py:341`. The value goes through `expanduser`. vLLM reads env vars live from
  `os.environ` until `enable_envs_cache()` memoizes them after init `vendor/vllm-v0.32.0/vllm/envs.py:2322`, so later env
  changes are not seen. No serving code sets `VLLM_CACHE_ROOT`; only the startup benchmark points it at a `mkdtemp`
  dir `vendor/vllm-v0.32.0/vllm/benchmarks/startup.py:121`.
- **What lives under it:** the torch.compile caches (§2–6), `deep_gemm/` (§7, only when the launcher leaves it unset),
  `flashinfer_autotune_cache/` (§9), `startup_plan/` (§10), `gpu_p2p_access_cache_for_*.json` (§11), `modelinfos/`
  (§12) and `dummy_cache/` (§3). `VLLM_ASSETS_CACHE` is *not* under it (§17).
- **Engine side effects at `import vllm`.** `import vllm` runs `env_override` `vendor/vllm-v0.32.0/vllm/__init__.py:14`.
  That module force-sets `TORCHINDUCTOR_COMPILE_THREADS=1` `vendor/vllm-v0.32.0/vllm/env_override.py:168`, and
  `setdefault`s `TRITON_CACHE_AUTOTUNING=1` `vendor/vllm-v0.32.0/vllm/env_override.py:176`, so Triton persists its
  `@triton.autotune` results in whatever Triton cache dir is active. It also `setdefault`s
  `TILELANG_CLEANUP_TEMP_FILES` (§13).
- **Key: `envs.compile_factors()`.** These are the env factors of both torch.compile keys (§2, §6). Every
  registered env var is hashed unless it is on an ignore list `vendor/vllm-v0.32.0/vllm/envs.py:2354`
  `vendor/vllm-v0.32.0/vllm/envs.py:2448`.
  - **Ignored (location-only):** `VLLM_CACHE_ROOT` `vendor/vllm-v0.32.0/vllm/envs.py:2364` and `LD_LIBRARY_PATH`
    `vendor/vllm-v0.32.0/vllm/envs.py:2374`. The stated reason is that hashing location-only paths would invalidate every
    cache when HOME or the XDG roots move `vendor/vllm-v0.32.0/vllm/envs.py:2368`. Also ignored: `VLLM_CONFIG_ROOT`,
    `VLLM_FLASHINFER_AUTOTUNE_CACHE_DIR`, `VLLM_TUNED_CONFIG_FOLDER`, `VLLM_ASSETS_CACHE`, `LOCAL_RANK`,
    `CUDA_VISIBLE_DEVICES`, `VLLM_HOST_IP`, `VLLM_PORT` and `VLLM_FORCE_AOT_LOAD`.
  - **Hashed:** parsing `envs.py` shows 240 of the 316 registered variables are hashed. The hashed set includes
    paths, ranks and ports:
    - `CUDA_HOME` `vendor/vllm-v0.32.0/vllm/envs.py:749`
    - `VLLM_NCCL_SO_PATH`, `VLLM_CUDART_SO_PATH`, `VLLM_NCCL_INCLUDE_PATH`, `VLLM_LORA_RESOLVER_CACHE_DIR` and
      `VLLM_RUST_FRONTEND_PATH`
    - `VLLM_DP_RANK` `vendor/vllm-v0.32.0/vllm/envs.py:1515`, `VLLM_DP_RANK_LOCAL` and `VLLM_DP_SIZE`
    - the side-channel ports `VLLM_NIXL_SIDE_CHANNEL_PORT` `vendor/vllm-v0.32.0/vllm/envs.py:1739`,
      `VLLM_P2P_SIDE_CHANNEL_PORT` and `VLLM_MOONCAKE_BOOTSTRAP_PORT`
    - every tuning flag, for example `VLLM_DEEP_GEMM_WARMUP`, `VLLM_ALLREDUCE_USE_SYMM_MEM` (which `vllm_base.toml`
      sets `vendor/model-launch/src/swiss_ai_model_launch/assets/envs/vllm_base.toml:31`) and `VLLM_COMPILE_CACHE_SAVE_FORMAT`.

    `RAY_EXPERIMENTAL_NOSET_*` are appended as well `vendor/vllm-v0.32.0/vllm/envs.py:2485`. An unset variable hashes as `None`.
    So these entries split the cache only when a launcher sets them per job or per rank.

## 2. torch.compile AOT artifact (default path): location, override, key (`vllm_aot`)

1. **Variable and default.**
   - `VLLM_USE_AOT_COMPILE` defaults on for torch ≥ 2.10 unless `VLLM_DISABLE_COMPILE_CACHE=1`
     `vendor/vllm-v0.32.0/vllm/envs.py:382` `vendor/vllm-v0.32.0/vllm/envs.py:374`.
   - `VLLM_USE_MEGA_AOT_ARTIFACT` defaults on for torch ≥ 2.12 whenever AOT is on `vendor/vllm-v0.32.0/vllm/envs.py:393`.
   - The location depends only on `VLLM_CACHE_ROOT`:
     `$VLLM_CACHE_ROOT/torch_compile_cache/torch_aot_compile/<sha256>/rank_<rank>_<dp_index>/model`
     `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:568` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:584` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:585`.
   - `compilation_config.cache_dir` (`-cc.cache_dir`) is not read on this path. It only affects §6.
2. **Engine override.** Before the load attempt, vLLM sets `TORCHINDUCTOR_CACHE_DIR=<hash dir>/inductor_cache`
   `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:574` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:580`.
   - The override is unconditional and process-wide, so any value the launcher set is lost.
   - The reason given is that torch may already have written its `/tmp` default into `os.environ`
     `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:578` `vendor/src/pytorch-v2.13.0/torch/_inductor/runtime/cache_dir_utils.py:19`.
   - The hash-level dir, including `inductor_cache`, is shared by the ranks `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:572`. The
     `model` files are per rank.
3. **Key.** The dir name is the full 64-hex `sha256(str(factors))` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:564`. The factors start from
   `aot_compile_hash_factors()` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:561` and are:
   - the env hash of §1 `vendor/vllm-v0.32.0/vllm/compilation/caching.py:576`
   - `VllmConfig.compute_hash()` `vendor/vllm-v0.32.0/vllm/compilation/caching.py:581`. This covers the vLLM version, the model path string
     and every graph-relevant config (§4).
   - when mega is on, the Inductor factors `vendor/vllm-v0.32.0/vllm/compilation/caching.py:586`: GPU name, `torch.version.cuda`, the
     Triton key, a hash of the torch build, and the Inductor and functorch configs (§4)
   - `_model_hash_key(forward)` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:563`, which is the vLLM version, the forward's qualname and its
     first line number `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:260` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:262`.

   Traced source files are deliberately left out of the dir hash and checked at load instead
   `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:551`. Also not in the key:
   - the driver version
   - the compute capability as a number (the GPU name stands in for it)
   - the Python version
   - any filesystem path other than strings inside configs, such as `model`.

## 3. torch.compile AOT artifact: write, read, relocate, content (`vllm_aot_io`)

3. **Write pattern.** After compiling, vLLM writes `<model>.<pid>.tmp` and then `os.replace`s it onto `model`
   `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:739` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:741`.
   - There is no lock. Errors are only logged `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:750`.
   - The save is skipped when the function was loaded from disk `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:727`.
   - Concurrent jobs each publish a complete file, and the last rename wins.
   - The tmp name is unique per PID only. Two nodes with the same PID that write the same `rank_*` file on shared
     storage could therefore write into one tmp file. If that happens, the next load fails and the model recompiles.
4. **Relocatability.**
   - The key holds no install or cache path. Its only path-like inputs are config strings such as `model` (§4).
   - vLLM pickles a state dict `vendor/vllm-v0.32.0/vllm/compilation/caching.py:304` that holds the FX graph, the example inputs as `meta`
     tensors `vendor/vllm-v0.32.0/vllm/compilation/caching.py:281`, the generated execution code, and every Inductor artifact as bytes
     `vendor/vllm-v0.32.0/vllm/compilation/caching.py:301`, deduplicated by SHA-256 `vendor/vllm-v0.32.0/vllm/compilation/caching.py:43`. None of what vLLM adds
     needs a path to load.
   - The load-time source check re-reads files at the *current* module paths
     `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:274`. Moving the install therefore does not invalidate by itself; only content
     changes do.
   - Whether torch's Dynamo or Inductor serialization embeds paths is **UNVERIFIED**:
     `torch/_dynamo/aot_compile.py` and `torch/_inductor/standalone_compile.py` are not vendored.
5. **Hit/miss check.** No load is attempted when `VLLM_DISABLE_COMPILE_CACHE` is set
   `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:586`. Otherwise:
   - vLLM opens `model` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:303` and calls `torch.compiler.load_compiled_function`
     `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:305`.
   - It then verifies the traced source contents; a mismatch recompiles `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:281`.
   - Any exception, including `EOFError` on a truncated file, is logged and the model recompiles
     `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:328` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:334`. A half-written file is therefore rebuilt, not fatal.
     The exception is `VLLM_FORCE_AOT_LOAD=1`, which makes load failures fatal `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:339`.

   **A read-only cache directory is not safe here.** Even on a hit:
   - vLLM `makedirs` `<hash>/inductor_cache` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:575`.
   - On the mega path it also creates `$VLLM_CACHE_ROOT/dummy_cache` `vendor/vllm-v0.32.0/vllm/compilation/caching.py:481`
     `vendor/vllm-v0.32.0/vllm/compilation/caching.py:482`. Both calls are fine if the dirs already exist.
   - vLLM's own comment says that post-load execution, CUDA-graph capture and later autotune or recompile write under
     `<hash>/inductor_cache/` `vendor/vllm-v0.32.0/vllm/compilation/decorators.py:577`.
   - If `dummy_cache` cannot be created, the load fallback swallows the error and the hit becomes a recompile. That
     recompile's writes then fail outside any handler. This is inferred from the cited code and was not run.
6. **Content classes.**
   - `rank_<r>_<dp>/model`: one pickle blob per rank holding every compiled graph and kernel, for all compile ranges.
   - `rank_*/model.<pid>.tmp`: leftovers from a crash.
   - `inductor_cache/`: Inductor's own tree. It holds FX-graph and AOTAutograd entries, generated wrapper `.py` files,
     and Triton kernels under `triton/<dev>` unless `TRITON_CACHE_DIR` is set (§5). The layout is covered by the
     PyTorch topic.
   - `$VLLM_CACHE_ROOT/dummy_cache/`: an empty dir.
   - On a miss, vLLM also creates the §6 dir, holding `cache_key_factors.json` and `computation_graph.py`.

## 4. Config hash and Inductor "system" factors behind both compile keys (`vllm_hash`)

- `VllmConfig.compute_hash()` starts with the vLLM `__version__` `vendor/vllm-v0.32.0/vllm/config/vllm.py:471`. It then adds the hash of
  each sub-config, among them the model config `vendor/vllm-v0.32.0/vllm/config/vllm.py:473` and the compilation config
  `vendor/vllm-v0.32.0/vllm/config/vllm.py:533`.
- Each sub-config hash covers every dataclass field that is not explicitly ignored `vendor/vllm-v0.32.0/vllm/config/utils.py:382`.
  `ModelConfig.model` is one of those fields: the HF repo id or the local path string `vendor/vllm-v0.32.0/vllm/config/model.py:154`.
  Serving the same weights from a different path therefore gives a different cache.
- The compilation config ignores its own path fields (`cache_dir`, `local_cache_dir`, `debug_dump_path`)
  `vendor/vllm-v0.32.0/vllm/config/compilation.py:802`. The parallel config ignores rank, DP rank and master address
  `vendor/vllm-v0.32.0/vllm/config/parallel.py:899`.
- **Device identity is absent from `VllmConfig.compute_hash()`** `vendor/vllm-v0.32.0/vllm/v1/worker/startup_plan.py:48`. GPU identity enters only
  through the Inductor factors:
  - `CacheBase.get_system()` `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:170`, which records the GPU name, `torch.version.cuda` and the Triton
    key `vendor/src/pytorch-v2.13.0/torch/_inductor/codecache.py:298` `vendor/src/pytorch-v2.13.0/torch/_inductor/codecache.py:299` `vendor/src/pytorch-v2.13.0/torch/_inductor/codecache.py:289`
  - `torch_key()` `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:176`.

  So the mega-AOT key (§2) and the legacy key (§6, through `compiler_hash`) both cover the GPU model and the
  CUDA, Triton and torch builds. The non-mega AOT key does not.

## 5. Where Inductor and Triton actually write (`vllm_inductor`)

1. **Variables.** `VLLM_USE_STANDALONE_COMPILE` defaults to 1 `vendor/vllm-v0.32.0/vllm/envs.py:764`, which
   selects `InductorStandaloneAdaptor` `vendor/vllm-v0.32.0/vllm/compilation/backends.py:109`.
   - In that adaptor, the per-compile `initialize_cache` only records the directory
     `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:272`. In the default path, the AOT override of §2 is therefore the
     only redirection.
   - The legacy `InductorAdaptor` runs only with `VLLM_USE_STANDALONE_COMPILE=0`. It sets
     `TORCHINDUCTOR_CACHE_DIR=<base>/inductor_cache` `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:467`. Unless the caller set
     `TRITON_CACHE_DIR`, it also sets `TRITON_CACHE_DIR=<base>/triton_cache` `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:471`
     `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:472`.
2. **Defaults when vLLM does not redirect.**
   - torch's `cache_dir()` resolves `TORCHINDUCTOR_CACHE_DIR`, else `/tmp/torchinductor_<user>`
     `vendor/src/pytorch-v2.13.0/torch/_inductor/runtime/cache_dir_utils.py:33`, and writes the absolute path back into `os.environ`
     `vendor/src/pytorch-v2.13.0/torch/_inductor/runtime/cache_dir_utils.py:19`.
   - For Triton, torch uses `TRITON_CACHE_DIR` if set, else `<inductor dir>/triton/<device>`
     `vendor/src/pytorch-v2.13.0/torch/_inductor/runtime/cache_dir_utils.py:38`. The first `CachingAutotuner` exports that path into `os.environ`
     process-wide `vendor/src/pytorch-v2.13.0/torch/_inductor/runtime/triton_heuristics.py:493`.
3. **Consequence.** Take the default AOT path with no `TRITON_CACHE_DIR` set by the launcher:
   - Inductor's Triton kernels land in `torch_aot_compile/<hash>/inductor_cache/triton/<dev>`. So does any vLLM
     `@triton.jit` kernel JIT'd after that point, because Triton's cache-dir knob `vendor/src/triton-3.7.1-5d6048a/python/triton/knobs.py:347`
     re-reads the env on every access `vendor/src/triton-3.7.1-5d6048a/python/triton/knobs.py:118`. This is a fresh Triton cache for every
     compile hash.
   - Kernels JIT'd before that point go to Triton's own default.
   - servekit sets `TRITON_CACHE_DIR` `vendor/servekit/src/servekit/jit_cache.py:17`, which pins all of them to one dir.
   - Triton's key and write pattern are covered by the Triton topic.

## 6. Legacy / non-mega torch.compile dir `torch_compile_cache/<hash10>` (`vllm_tcc`)

**When this dir is used.** It applies when:
- `VLLM_USE_MEGA_AOT_ARTIFACT=0` (non-mega AOT loads re-enter this path),
- `VLLM_USE_AOT_COMPILE=0`, or
- `-cc.cache_dir` is given.

In the default mega mode, compiles return no handle `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:380`, and entries are recorded only
when a handle exists `vendor/vllm-v0.32.0/vllm/compilation/backends.py:373`. A miss therefore leaves only `cache_key_factors.json` and
`computation_graph.py` here.

1. **Variable and default.** `compilation_config.cache_dir` if set `vendor/vllm-v0.32.0/vllm/compilation/backends.py:1065`, else
   `$VLLM_CACHE_ROOT/torch_compile_cache/<hash10>` `vendor/vllm-v0.32.0/vllm/compilation/backends.py:1075`. Below that comes
   `rank_<rank>_<dp>/<prefix>` `vendor/vllm-v0.32.0/vllm/compilation/backends.py:1084`.
2. **Key.** `sha256(str([env_hash, config_hash, code_hash, compiler_hash]))[:10]` `vendor/vllm-v0.32.0/vllm/compilation/backends.py:1070`
   `vendor/vllm-v0.32.0/vllm/compilation/backends.py:1073`.
   - `code_hash` hashes each traced file's **absolute path** together with its content `vendor/vllm-v0.32.0/vllm/compilation/backends.py:1055`. The
     install prefix is therefore part of the key.
   - `compiler_hash` is the Inductor factors of §4, truncated to 10 hex `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:265`.
   - 40 bits of dir name, and the recorded factors are never compared on load.
3. **Write pattern.**
   - Each compiled range is saved as `artifact_compile_range_<start>_<end>_subgraph_<i>` `vendor/vllm-v0.32.0/vllm/compilation/backends.py:310`
     by torch `CompiledArtifact.save(format=...)` `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:406`.
   - vLLM backports the atomic `write_atomic` save only for torch < 2.10 `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:206`. On torch
     2.13, atomicity is upstream's (PyTorch topic).
   - `VLLM_COMPILE_CACHE_SAVE_FORMAT` `vendor/vllm-v0.32.0/vllm/envs.py:2148` set to `unpacked` writes directories, and vLLM
     documents that as not multi-process safe `vendor/vllm-v0.32.0/vllm/envs.py:2145`.
   - The index `vllm_compile_cache.py` is rewritten in place with a plain `open(..., "w")`, with no tmp file and no
     lock `vendor/vllm-v0.32.0/vllm/compilation/backends.py:223`.
   - `cache_key_factors.json` is written once if absent, and errors are swallowed `vendor/vllm-v0.32.0/vllm/compilation/backends.py:1132`
     `vendor/vllm-v0.32.0/vllm/compilation/backends.py:1133`.
   - `computation_graph.py` is written if absent, without a guard `vendor/vllm-v0.32.0/vllm/compilation/backends.py:1271`.
4. **Relocatability.** Moving the dir alone does not break it: at load, the artifact path is rebuilt from the current
   cache dir `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:421`. A different install prefix does change the key, though (point 2).
5. **Hit/miss check.**
   - An index entry is looked up and loaded with `CompiledArtifact.load` `vendor/vllm-v0.32.0/vllm/compilation/compiler_interface.py:422`.
   - A malformed entry is treated as a miss `vendor/vllm-v0.32.0/vllm/compilation/backends.py:249`.
   - The index file itself is parsed with `ast.literal_eval` outside any try `vendor/vllm-v0.32.0/vllm/compilation/backends.py:194`. An index
     torn by a concurrent in-place rewrite therefore raises.
   - On a hit with a read-only directory, vLLM only reads and runs `makedirs`/`exists`. It writes only when a file is
     missing or an entry is new.
6. **Content classes.** `artifact_compile_range_*` (a binary file, or a directory when unpacked),
   `vllm_compile_cache.py` (the Python-literal index), `cache_key_factors.json` and `computation_graph.py`.

## 7. DeepGEMM JIT cache (`vllm_deepgemm`)

1. **Variable and default.** `DG_JIT_CACHE_DIR` `vendor/vllm-v0.32.0/vllm/utils/deep_gemm.py:279`.
   - Inside `_lazy_init()`, vLLM sets it to `$VLLM_CACHE_ROOT/deep_gemm` only if it is unset or empty
     `vendor/vllm-v0.32.0/vllm/utils/deep_gemm.py:280` `vendor/vllm-v0.32.0/vllm/utils/deep_gemm.py:282`.
   - vLLM prefers a pip-installed `deep_gemm` `vendor/vllm-v0.32.0/vllm/utils/deep_gemm.py:194`. Otherwise it uses the copy
     vendored in the wheel `vendor/vllm-v0.32.0/vllm/utils/deep_gemm.py:205` `vendor/vllm-v0.32.0/cmake/external_projects/deepgemm.cmake:97`. Which of the two
     `vllm_base` contains is **UNVERIFIED**.
   - DeepJIT reads `<prefix>_JIT_CACHE_DIR`, then the global `DJ_JIT_CACHE_DIR` `vendor/src/DeepJIT-3732a3b/include/deep_jit/utils/env.hpp:69`,
     then falls back to `$HOME/.dj` `vendor/src/DeepJIT-3732a3b/include/deep_jit/cache/disk.hpp:105`. vLLM's `DG_` default therefore takes
     precedence over a launcher-set `DJ_JIT_CACHE_DIR`.
2. **Timing.**
   - `has_deep_gemm()` trial-imports DeepGEMM before the env var is set `vendor/vllm-v0.32.0/vllm/utils/import_utils.py:519`. That is
