# Coding-agent security in a private research workspace (evidence through 12 Nov 2026)

Method note. I opened about 20 pages in full (vendor docs, arXiv abstracts, Check Point, Anthropic posts, Willison, CSA notes, Grith). The rest of the ledger rests on search-result summaries only; those rows say "(search summary)". Several primary posts (Meta's Rule of Two, Adnan Khan's Clinejection, Rehberger's auto-mode post, Invariant's blog, system cards) were not opened. Their figures come from relays and are flagged. Grades: A controlled study, B measured case or reproduced exploit, C practitioner report, D vendor claim, E opinion.

## Bottom line

1. **Never let one session hold all three of: untrusted content, private data, and an outward channel.** Untrusted content means clones, issues, web pages and packages. Private data means unpublished results, drafts and tokens. An outward channel means any credential for push, `gh`, email, Modal or Hugging Face, or unrestricted network egress. For this setting the untrusted and private legs are hard to drop, so drop the third: no outward credentials and default-deny egress in agent sessions. Confidence: high. Ledger: S01, S02, S03, S18, S19, S22, S24.
2. **Keep push, `gh`, Modal, Hugging Face and email credentials out of every agent session, including the agent's sandbox and its readable files. Use a human-only export step.** Real incidents were token theft followed by publishing (S18, S22, S23). Anthropic's own cloud design keeps the GitHub credential outside the VM (S09). A keychain entry alone is not enough, because an agent running as the same macOS user may be able to call the same tools. Run agents in a container or VM, or deny credential paths in the sandbox config (S07). Confidence: high on removing the credentials, medium on keychain-only. Ledger: S07, S09, S18, S22, S23.
3. **Do not treat prompt-injection filtering, including classifier "auto mode", as a security boundary.** Adaptive attackers beat 12 published defences, mostly above 90% (S02). An independent stress test of auto mode measured an 81% false-negative rate on ambiguous state-changing actions, against Anthropic's 17% on a small real set (S15, S12). A working code-execution chain against Opus 5 in auto mode succeeded in 3 of 5 and 4 of 5 trials, and Anthropic called auto mode a best-effort convenience (S16). Use auto mode only inside an isolation boundary. Confidence: high. Ledger: S02, S12, S13, S15, S16, S32.
4. **For unattended or skip-permissions runs, put the whole agent process in a container, microVM or `srt` sandbox with allowlisted egress. The Bash-only sandbox is not enough.** Anthropic's docs say the Bash sandbox is not sufficient for fully unattended runs. They also say Read, Edit, WebFetch, hooks and MCP servers sit outside it (S07, S08). Sandbox escapes were patched in 2026 (S31, search summary), and an allowlisted first-party domain was used to exfiltrate (S36). Confidence: high. Ledger: S07, S08, S31, S36.
5. **Treat instruction files inside cloned repositories as untrusted input, and configure for it.** Claude Code loads subdirectory `CLAUDE.md` and `AGENTS.md` files on demand once the agent reads a file there, and calls them context, not enforced rules (S10). Use `claudeMdExcludes` for the clone directory. Do not run headless `claude -p` inside a clone, because it skips the trust dialog and still uses repo hooks (S11). Repository-controlled settings gave code execution and key exfiltration before the trust dialog in 2025 (S17). Poisoned rule files steered agents in controlled tests, up to 84% (S28). Confidence: medium. Ledger: S10, S11, S17, S20, S28, S29.
6. **Split reader and actor by filesystem, not by prompt.** The session that reads upstream repos, issues and web pages sees only the one clone plus a task file, with no drafts, results or credentials. Private notes and results live outside the mounted tree. Patches come back as text to the human. This is the Rule of Two and the design-pattern papers applied at laptop cost (S03, S05). Confidence: medium. CaMeL-style provable designs cost utility (77% vs 84% on AgentDojo, S04) and are not packaged for coding agents.
7. **Run untrusted code (upstream tests, `pip install`, build scripts) only in a throwaway container with no secrets and no host mounts. Fetch dependencies first, then cut the network for the run.** Prefer wheels, and use `--require-hashes` and `--no-build` where possible (S39). Hashes prove integrity, not honesty (S39). Willison names a malicious package that tells the agent to run a helper that exfiltrates as a case auto mode may not stop (S14). `python -I` helps against the cwd module-shadowing step in S16, as my inference, not a tested control. Confidence: medium. Ledger: S14, S16, S23, S34, S35, S39.
8. **Make patch export a human-only, scripted gate.** Run `git format-patch`, then a path allowlist (fail on anything outside the intended tree), then gitleaks, optionally trufflehog with verification, then a custom grep for private paths, names, emails and project codenames. Then read the diff yourself. Scanner recall is poorly measured (S40), so the scanners are a net, not proof. Confidence: medium-low (weak evidence, strong engineering logic). Ledger: S22, S40.
9. **Cap spend structurally.** The Modal token lives only in the human's shell. Agent-triggered GPU runs go through a human-launched wrapper with a hard cap, and I found no source for a Modal-side spend limit (see Not verified). Confidence: medium (inference from S18, S22, S23, where stolen publish and cloud tokens were the damage).
10. **Do not give agents the GitHub MCP server, or any token that spans public and private repos, in a session that reads public issues. Do not add AI issue-triage Actions with write tokens to your forks.** Both produced documented leaks or takeovers (S19, S18, S24, S26). Confidence: high.

## Disagreements

- **Can a model or classifier be trusted to resist injection well enough for unattended use?**
  - For: Anthropic reports 0 of 720 successes in auto mode and 89% vs 13.6% for humans (S13), plus per-model system-card rates that fall each generation (S32, S33).
  - Against: Rehberger reproduced code execution at 60-80% against the same generation (S16). Ji et al. measured an 81% miss rate on ambiguous actions (S15). The 12-defence study shows static evaluations overstate robustness (S02). Willison wants independent replication (S14).
  - Reconciling: the tests differ in workload, attacker adaptivity, and whether the attack is a chain of individually benign steps. Anthropic's own docs say auto mode is not an isolation boundary (S08) and the vendor responded to S16 as outside the classifier's scope (S16, single relay). For this setting the evidence favours the sceptics: one injection that gets through costs unpublished work or a token, while the cost of isolation is small.
- **Is the Bash sandbox enough?** Anthropic's engineering post presents it as safer and quieter (84% fewer prompts, S06). The same vendor's docs say it is insufficient for fully unattended runs and list large exclusions (S07, S08). Security researchers report escapes (S31) and an allowed-domain exfil (S36). Evidence favours "necessary, not sufficient".
- **Where the Rule of Two is incomplete.** Willison endorses it as best current practice but notes a diagram flaw: untrusted input plus state change is not safe (S01). Commentators argue it ignores intent translation and multi-step designs (secondary, not graded or ledgered). For a solo researcher it is still the cheapest usable rule, and the unpublished-work leg can be removed by filesystem separation (S03).
- **Are instruction files in clones a real threat?** Vendor docs say they are context that the model may follow or not (S10) and show an on-demand load with an opt-out glob. Researchers show planted instruction files steering agents (S28, S29, S20) and Cursor and Copilot vendors have called some of it user responsibility (S20). The only measured numbers are on older tool versions (S28) or a self-reported compilation (S29). The evidence favours caution because the opt-out costs one config line.
- **Reader and actor split vs design patterns that need a bespoke agent runtime.** CaMeL-style designs give provable properties at a utility cost (S04). Practical coding workflows cannot easily adopt them (S05 says general agents are hard). For one student the filesystem and credential split gets most of the benefit.

## Disconfirming evidence and null results

- **Claim: frontier models are now robust enough to run unattended with network and credentials.**
  - Supporting evidence exists: 0 of 720 in third-party tests (S13), falling system-card rates (S33).
  - Disconfirming: S16 (3/5 and 4/5), S15 (81% miss rate), S02 (adaptive attackers), S32 (63% at 100 attempts for Opus 4.5), S29 (Downloads-folder AGENTS.md worked on Codex above 90% of attempts), S26 and S18 (credential-scope failures that robustness would not fix).
  - Verdict: not supported for this setting. Even a 1% per-attempt rate (S32) is unacceptable when a single success can leak work or spend credit, and attackers can retry.
- **Claim: sandboxing makes skip-permissions mode safe.**
  - Disconfirming: Anthropic's own docs say the Bash sandbox does not cover file tools or MCP and is insufficient for unattended runs (S07, S08). Three 2026 sandbox bugs in Claude Code (S31), a Cursor sandbox escape (S30), an allowed-domain exfil path (S36), and bypass-flag misuse in the wild by malware (S22).
  - Verdict: false as stated. True only for a whole-process sandbox with default-deny egress and no secrets inside.
- **Claim: instruction files inside a cloned repository are harmless.** Disconfirmed by S17, S20, S28, S29, S25. No source found showing real-world theft of a researcher's private data this way.
- **Null results.**
  - I found no documented incident where an agent on a personal laptop pushed or posted private research because of a cloned-repo instruction file. Documented real harms were CI agents with write tokens (S18, S24, S26) and package-level malware (S22, S23).
  - I found no independent replication of Anthropic's 0 of 720 figure and no independent benchmark of gitleaks or trufflehog recall on agent-generated patches (S40).
  - I found no source on Modal's own spend-limit behaviour, none on how Cursor, Gemini CLI or Copilot discover instruction files in subdirectories, and no published effectiveness measurement of `python -I` or network-off containers against injection.
  - Searches used: Rule of Two, Attacker Moves Second, CaMeL, design patterns, Clinejection, PromptPwnd, GitHub MCP, rules file backdoor, Nx, Shai-Hulud, slopsquatting, pickle, auto mode classifier numbers, sandbox escape CVEs, AGENTS.md discovery, Codex sandbox, uv hashes, secret scanners.

## Transfer notes

- **Practical for one student on a laptop (cheap, no team):**
  - Separate macOS user or a container for agent work, so Keychain, `~/.ssh`, `~/.config/gh`, `~/.modal.toml` and similar files are not readable. Setting `sandbox.credentials` or `denyRead` also covers the default read policy that allows credential files (S07).
  - No `gh auth`, no ssh agent, no push remotes in agent sessions (S18, S22). Add the remotes only in the human shell at export.
  - `claudeMdExcludes` for the clones directory, plus an `InstructionsLoaded` hook that logs loads (S10).
  - Launch `srt claude` (sandbox runtime, beta, network denied by default, writes limited) or a Docker or colima container with only the target clone mounted (S08). Docker Sandboxes (a microVM) is a free option named in the Anthropic docs (S08). Note the Bash sandbox is incompatible with `docker` commands (S07).
  - Network: allow the model API and the package index only. Recognise that GitHub and the model API can themselves be exfil paths (S22, S36), so do not allowlist more than needed.
  - Hash-pinned installs with `--require-hashes`, wheels only (S39); `python -I` for scripts that run in untrusted directories (my inference from S16).
  - Export script: format-patch, path allowlist, gitleaks, grep list of private strings, human read.
- **Enterprise-only, skip:** managed settings, server-managed policy, process-creation monitoring (EDR), AARM-style runtime enforcement, signed instruction files (S16, S29).
- **Setting-specific combinations to forbid in one session:**
  - Clones or web or issues + private drafts and results + any network beyond the model API.
  - Clones + any push, `gh` or email credential.
  - Web or issues + Modal token (spend).
  - Package install or test run + home directory access.
  - GitHub MCP with a token spanning private repos + public issues (S19).
- **Priority order for this student's goals:** (1) patch quality is protected by the human reading every line, which also acts as the outward gate; (2) productivity cost of the controls is low because the 84% prompt reduction (S06, vendor) comes from sandboxing, not from relaxing the boundary; (3) the controls are tool-neutral (containers, credentials, export script), so they survive switching tools.
- **Claude Code headless caution:** scripting `claude -p` across the 30 clones skips the trust dialog and still uses repo hooks and env (S11). Run such loops only inside the container.

## What better models change, and what they don't

- **Likely to change:** per-attempt injection success on standard benchmarks (S32 to S33: 4.7% at k=1 for Opus 4.5 down to 0.2-2% for Opus 5 per vendor relays); classifier miss rates; refusal behaviour when malware calls agent CLIs (S22). Re-check these each generation, because the evidence in S12, S13, S15 is tied to specific model versions.
- **Unlikely to change:**
  - The need for an architecture-level split. Attackers get repeated tries (S32 shows 63% at 100 attempts), and adaptive attacks beat defences tuned to a fixed attack set (S02).
  - Multi-step benign-looking chains (S16).
  - Credential scope and CI wiring bugs (S18, S26, S24).
  - Client-side trust and config bugs (S17, S27, S30).
  - Supply-chain code that never touches the model (S22, S23, S35).
  - Slopsquatting depends on model but cannot be fully eliminated, and hallucination rates vary by model (S34).
- **Interpretation:** a more robust model lowers the probability of compromise, but the controls in the Bottom line cap the damage when it fails. Their cost does not scale with model quality.
