# Context portability: one instruction source, thin adapters (research notes, 12 Nov 2026)

Scope note. Doc pages are dated by the version markers they carry (Claude Code v2.1.x), because most vendor pages show no date; every page was read on 12 Nov 2026. Local facts checked on the user's machine on 12 Nov 2026: GNU Make 3.81, Apple Git 2.50.1, and `just`, `mise` and `task` are all absent. These are labelled C00 in the ledger.

## Bottom line

1. **Make `AGENTS.md` the single source, flat and self-contained (no `@imports` inside it), and put it at the control-plane root.** Claude Code now reads it natively (v2.1.277 or later), Codex, Cursor, Copilot, OpenCode and Amp read it natively, and Gemini reads it after one setting. Confidence: high. Ledger: C01, C07, C13, C14, C16, C17, C19, C20, C10, C24.
2. **Keep one thin `CLAUDE.md` whose first line is `@AGENTS.md`, followed by only Claude-only lines. Do not use a symlink.** This is the documented approach for a project that has any `CLAUDE.md` or `CLAUDE.local.md`. A bare `AGENTS.md` is silently skipped as soon as any `CLAUDE.md` or `CLAUDE.local.md` exists in or above the working directory. Symlinks block Claude's Edit and Write tools. Confidence: high. Ledger: C01.
3. **Second agent: Codex CLI, with no adapter beyond the file itself. Gemini needs `context.fileName` set to include `AGENTS.md`, and Aider needs `read: AGENTS.md`.** The mechanism for Aider is documented for `CONVENTIONS.md`, but native `AGENTS.md` detection is UNVERIFIED. Confidence: high for Codex, medium for Gemini, low for Aider. Ledger: C07, C10, C21, C22, C23.
4. **Length and content rule: commands, constraints and traps an agent cannot infer, and nothing else. Treat 60 to 100 lines as a heuristic, not a measured threshold.** The only controlled evidence says repository overviews did not help, context-file length showed no clear relation to success or cost, and LLM-written files cost about 20% more without a reliable gain. Developer-written files were roughly neutral to slightly positive. Vendor guidance says under 200 lines (Claude) or under 500 (Cursor), and one practitioner reports 60. Confidence: high on content, low on the exact number. Ledger: C26, C27, C28, C29, C30, C01, C05, C13.
5. **Nested instruction files only where a folder has rules an agent cannot infer, each under about 30 lines, never repeating the parent, and never inside upstream clones.** Conflicts are resolved "arbitrarily" per Claude's docs, and subdirectory files have a smaller per-file cap. Put overrides for a clone in the project folder above it. Confidence: medium. Ledger: C01, C04, C07, C31.
6. **Stop third-party instruction files from loading by controlling the launch directory first, and `claudeMdExcludes` second. Do not run `claude -p` inside an untrusted clone without `--bare`.** The clone's skills load automatically, and `-p` runs the clone's project hooks and MCP servers without any trust dialog. Confidence: high on the docs, medium on the per-tool nuance. Ledger: C01, C02, C06, C07, C10, C16, C17, C19, C20.
7. **Command runner: plain `make` now, as a menu over `scripts/*.sh`. Do not install `just` for its own sake.** `make` is preinstalled (3.81, so no `$(file ...)` and other 4.x features) and `just` is not. I found no measured evidence that agents use either one more reliably; practitioner reports say Claude defaults to Makefile habits. Keep every target to one line calling a script so a later move to `just` is mechanical. Confidence: medium-low. Ledger: C00, C39, C42, C43.
8. **State files: keep few, split by writer. JSON (or a generated file) for state a program updates, append-only markdown for human decisions, and no "rewrite the handoff at every session end" ritual.** Anthropic's long-running-agent harness uses a progress file plus a JSON feature list plus git history, and says compaction alone was not enough. That evidence is vendor-grade and untested against alternatives. Claude's own docs prefer `/clear` plus a better prompt and re-inject plan files after compaction. Confidence: medium-low. Ledger: C34, C35, C05, C04.
9. **Deterministic guardrails live outside the instruction file: git hooks and a `make check` that any agent or human can run, plus Claude `PreToolUse` and `Stop` hooks for the few zero-exception rules. Keep the enforced set small.** Anthropic's own guidance says a line that keeps being ignored belongs in a hook, and that around forty hooks means most are preferences. Confidence: high. Ledger: C05, C01.
10. **Git layout: one canonical clone per upstream with `git worktree add` per parallel session, and set `worktree.useRelativePaths true`. Git 2.48 added relative worktree links, and 2.50.1 is installed.** Avoid `--reference` or `--shared` alternates unless you use `--dissociate`. Use `--filter=blob:none` only when the network is available at worktree creation. Confidence: medium (relative paths from the docs, option names from release notes plus memory). Ledger: C36, C37, C38, C03.

Claude and Codex both follow symlinked skill folders (C02, C08). So keep skill folders in `.agents/skills/<name>/` and symlink each one into `.claude/skills/<name>`. ## Disagreements

**D1. Does a context file help? Gloaguen et al. versus Lulla et al.** Gloaguen (C26): generated files raise cost by over 20% with no reliable success gain; developer files about +2.4 points on average but not significant. Lulla (C28): an AGENTS.md was associated with 28.64% lower median runtime and 16.58% fewer output tokens on 124 PRs in 10 repositories. Why they differ: different outcome (success and cost versus runtime and tokens), different file provenance, and Lulla is observational with a small sample. Fit for this setting: Gloaguen, because it is the larger controlled study and it measures the thing you care about first (correct patches). Neither supports a long file.

**D2. Is there a measured "short file" threshold? HumanLayer and Anthropic versus the controlled evidence.** HumanLayer (C30) says under 60 lines and about 150 to 200 instructions, built on IFScale (C29). Anthropic (C01) says under 200 lines; Cursor says under 500 (C13). Gloaguen found no clear relation between length and success or cost (C26). IFScale used a synthetic keyword task and 2025 models (C29). Fit: the vendors' numbers are budgets for attention, not findings. Use a short file because every line is paid for on every task (C05), not because 100 is a proven cliff.

**D3. Symlink versus import for Claude.** Anthropic documents both, and prefers the import when Claude-specific lines are needed (C01). Symlink drawbacks: Edit and Write refuse to write through it, and nothing can sit beside the shared text. Import drawback: Copilot CLI deduplicates identical copies but defines no precedence (C17), so a tool reading both `CLAUDE.md` and `AGENTS.md` sees the content twice only if it does not expand the import (UNVERIFIED for most tools). Fit: import, since you are on macOS (symlink Windows objection does not apply) but want a Claude-only section.

**D4. Where does state live? Anthropic's harness versus Anthropic's own newer docs.** C34 (Nov 2025) says compaction alone was not enough and uses fresh sessions rebuilt from a progress file and JSON. C05 and C04 say compaction is automatic, windows are 1M tokens on most current models, plan files are re-injected after compaction, and `/clear` is preferred between unrelated tasks. These are not strictly contradictory but the emphasis moved. Fit: take the artifacts (JSON checklist, git log, one-line status) and drop the ritual.

**D5. `just` versus `make`.** Proponents (C39, C43) cite argument handling and tab-free syntax; the counter-position (C42, C00, C43) is that `make` is already installed and agents default to Makefile idioms. No measurement either way. Fit: `make` as a thin menu, with the logic in scripts.

**D6. Does Claude Code read `AGENTS.md`? The user's two playbooks disagree.** Resolved: yes, from v2.1.277, but conditionally (C01). Playbooks that say "never" are stale; playbooks that say "always" miss the `CLAUDE.md`-present rule and the `CLAUDE.local.md` trap (C01).

## Disconfirming evidence and null results

- **"An AGENTS.md under about 100 lines helps."** I found no study that tests a 100-line threshold. The controlled study found length not clearly related to success or cost (C26). The "instruction budget" argument rests on a synthetic benchmark (C29) and is admitted by its popularizer to be non-rigorous (C30). Developer-written files improved success by about 2.4 points on average, not significantly (C26). Searches: Gloaguen full text, IFScale abstract, HumanLayer post, plus a general search for 2026 context-file studies.
- **"One source plus adapters works without drift."** No controlled drift study found. Documented mechanisms for drift are in the vendors' own pages: Claude skips `AGENTS.md` if any `CLAUDE.md` or `CLAUDE.local.md` is in or above the directory (C01); `AGENTS.md` loaded through the setting does not fire `InstructionsLoaded` hooks (C01); Copilot CLI has no defined precedence (C17); OpenCode picks only one of `AGENTS.md` and `CLAUDE.md` (C19); Amp falls back to `CLAUDE.md` only when `AGENTS.md` is absent (C20). A search for practitioner drift reports could not be completed (search quota exhausted), so the null is partial.
- **"`just` is the right runner."** No measured evidence for either runner; only anecdote that Claude leans toward Makefile syntax (C43). `just` is not installed here and `make` is 3.81 (C00, C42). Unverified in my reading: `just --list` behaviour, install route and stability (C39 intro page only).
- **"End every session by rewriting a handoff file."** No controlled evidence found for or against. The one detailed pattern (C34) is vendor-grade and uses an append-style progress file plus machine-checked JSON, not a rewrite. Claude's docs favour `/clear` and plan-file re-injection (C05, C04). Generated or optimized context text did not reliably beat no text (C32) and can stale (C32), which argues against a rewritten narrative as the main state carrier.
- **Skills and rules in general.** 92 of 98 skills had no significant effect and a few lost up to 17 points (C31); 307 skill-induced failures were catalogued (C33); an optimizer's +4.9 points was not significant (C32). So "add more skills" is not supported either.
- **Null results by omission.** I found no study of nested instruction files versus a single root file, and none of instruction files inside vendored clones.

## Transfer notes

Transfers from a team repository to a single-person control plane that wraps other people's repositories:
- Content rule (commands, constraints, traps; no overviews) transfers fully (C26, C01, C05).
- Hooks and scripts instead of prose for zero-exception rules transfer fully (C05).
- Launching from the right directory instead of editing exclusions transfers (C04).
- Worktree-per-session and one canonical clone transfer (C03, C36).

Does not transfer, or changes:
- Team-shared, PR-reviewed instruction files, `managed` policy files and per-directory owners (C04, C01) have no single-person analogue. Your review step is `make check` plus your own defence of each line.
- Unlike a team repo, the clones carry the upstream maintainers' own `AGENTS.md` or `CLAUDE.md`. For your priority (patches maintainers merge) you generally want the upstream file in force while editing the clone, because developer-written files were the less harmful kind (C26). Say in the root file that upstream contribution rules win for code inside a clone and control-plane rules win for process (inference).
- Security posture differs: a clone's skills, hooks, `.mcp.json` and `allowed-tools` can act with your permissions (C02, C06). Treat third-party clones as untrusted input, and run unattended `claude -p` there with `--bare` (C06).
- Project-root detection differs: Codex starts at the git root (C07), so launching Codex inside a clone would not see control-plane files above the clone's git root (inference from C07), while Claude loads every ancestor (C01) and Amp loads parents up to `$HOME` (C20). Launch agents from the project folder, not from inside a clone, unless you want the clone's context only.
- Auto memory is per git repo, machine-local and Claude-only (C01), so each clone gets its own and none carries to another tool. Keep decisions in files you own.

## What better models change, and what they don't

Likely to change (generation-dependent):
- Any instruction that works around a model weakness; Anthropic says to revisit after major releases (C04).
- Instruction-count ceilings: IFScale models were 2025-vintage (C29) and the 150-200 figure is secondhand (C30).
- Handoff and compaction advice written for smaller windows (C34 versus C05).
- Tool surface: AGENTS.md support in Claude arrived in v2.1.277 and changed again by v2.1.285 (C01); Codex already dropped `--full-auto` (C09); Gemini CLI was partly replaced by Antigravity on 18 Jun 2026 (C12); skills page versions moved through v2.1.309 (C02).
- Stronger models' generated files did not help more in Gloaguen's data (C26), so "let the better model write it" is not a safe bet.

Unlikely to change:
- Agents cannot infer which command is canonical, which paths are off-limits, or your one-writer rule, so those remain worth writing (C26, C05).
- Deterministic enforcement beats a model's judgement for rules without exceptions (C05, C01).
- Third-party content loaded automatically from clones remains a trust question (C02, C06).
- Git object-sharing mechanics (C36, C38).
