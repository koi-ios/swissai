## 12. First-timer traps
1. Pre-commit workflow fails for authors with fewer than 4 merged PRs unless a maintainer adds `ready`/`verified`; agents must not ask for it (`pre-commit.yml:44`).
2. CI is not run on push; a maintainer or trusted contributor must `/ci run`; new commits do not restart it (`README.md:346-352`).
3. PR branch must be zero commits behind base for `/ci run` (`README.md:353-363`).
4. Max 6 open PRs (`README.md:392-397`).
5. New files need the SPDX header (`check-spdx-header`), and new tests must be wired into `.buildkite/test_areas/*.yaml` (`check-test-tethering`, `tests/AGENTS.md:35-42`).
6. Docs required for user-visible changes (`README.md:276-290`; `AGENTS.md:34-36`).
7. Line length 88; Google-style docstrings in Markdown (`AGENTS.md:124-127`; `check-docstring-style`).
8. AI-assisted: PR body must state why it is not a duplicate, test commands and results, and (for output-affecting changes) model evals (`AGENTS.md:29-33`).
9. A squash merge drops the PR body; commit message is subject plus trailers (section 4); the PR title becomes the commit subject, so the `(#N)` is added by GitHub.
10. Draft PRs also need the pr-checklist skill run (`AGENTS.md:37`).
11. Don't use test shortcuts: no skip/xfail/loosened tolerances (`tests/AGENTS.md:17-22`).
12. Hook revs are frozen SHAs; do not bump them in unrelated PRs (diff hygiene; `pr-checklist` `:148`).
